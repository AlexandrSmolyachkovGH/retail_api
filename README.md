# Retail API
Сервис-обёртка над API сервиса [RetailCRM](https://www.retailcrm.ru/) для работы с клиентами, заказами и платежами.
___
### Технологии
- **Python 3.10**
- **FastAPI** - Асинхронный Веб-фреймворк;
- **httpx** – Асинхронный HTTP-клиент для запросов к внешнему API;
- **Pydantic v2** – Схемы запросов и ответов + конфигурационные файлы;
- **Poetry** — Управление зависимостями и сборкой проекта;
- **loguru** - Библиотека для настройки логирования;
- **pytest** - Фреймворк для написания тестов;
- **coverage** - Библиотека проверки процента тестового покрытия;
- **black, isort, mypy, flake8** - Форматирование кода и статический анализ;
- **Docker, Docker Compose** – Контейнеризация и оркестрация сервиса;
**GitHub Actions (CI)** — Прогон тестов и проверка покрытия в pipeline.
___
### Быстрый старт через Docker
1. Клонируем репозиторий:
```bash
git clone git@github.com:AlexandrSmolyachkovGH/retail_api.git
```
2. Переходим в проект:
```bash
cd retail_api
```
3. В корне проекта создаем .env файл и прокидываем настройки:
```
API_KEY="ПРИМЕР_ВАШЕГО_КЛЮЧА"
SUBDOMAIN="ПРИМЕР_ВАШЕГО_ДОМЕНА"
```
4. Собираем и запускаем контейнер:
```bash
docker compose up -d --build
```
5. Проверить успешно ли сервер поднялся можно:
- API: http://localhost:8088
- Swagger UI: http://localhost:8088/docs
- Health-check: http://localhost:8088/health
6. Для остановки контейнера:
```bash
docker compose down
```

### Функциональность
Реализованы эндпоинты:
1. **Получение списка клиентов**
   `GET /customers`
   - Возвращает список клиентов из RetailCRM.
   - Поддерживает фильтрацию по:
     - имени, фамилии, номеру телефона - `name`;
     - email - `email`;
     - дате регистрации - `dateFrom`, `dateTo`;
   - Поддерживает пагинацию - `limit`, `page`.

2. **Создание клиента**
   `POST /customers/create`
   - Создаёт нового клиента в RetailCRM.
   - Входные данные:
     - `firstName`;
     - `lastName`;
     - `email`;
     - `phone` (опционально);
     - `birthday` (опционально);
     - `vip`, `customFields`, `address` и др опциональные поля.

3. **Получение списка заказов клиента**
   `GET /orders`
   - Принимает `customerId`;
   - Возвращает список заказов, связанных с клиентом;
   - Есть пагинация (`limit`, `page`).

4. **Создание заказа**
   `POST /orders`
   - Создаёт заказ в RetailCRM связанные с клиентом.
   - Входные данные:
     - `number` — номер заказа;
     - `site` — сайт (опционально);
     - `customer` — идентификатор клиента (`id` + `contragent`);
     - `items` — список товаров (`productName`, `quantity`, `price`).

5. **Создание и привязка платежа к заказу**
   `POST /orders/create-payment`
   - Создаёт платёж и привязывает его к заказу.
   - Входные данные:
     - `order.id` — ID заказа;
     - `amount` — сумма;
     - `type` — тип платежа (`cash`, `bank-card`, `e-money`, ...);
     - `status` — статус (`not-paid`, `paid`, `fail`, ...).

Дополнительно:
- `GET /` — простая “root”-страница с описанием и ссылками (`/docs`, `/redoc`, `/health`).
- `GET /health` — health-check эндпоинт, возвращает `{ "status": "UP" }`.
